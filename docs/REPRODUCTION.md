# Reproducing protocol v2

Use Python 3.12 and one complete dependency profile. Install
`requirements/dev.txt` with `pip install --require-hashes`, then install
`torch==2.13.0+cpu --no-deps` from the official PyTorch CPU index. Run `pip check`.
The train-only profile does not include the complete DVC toolchain. GPU execution
requires a separately validated environment and is not covered by the CPU run.

Supply `data/raw/all_tickets_processed_improved_v3.csv` without resaving or
reordering it. Its required SHA-256 is
`044fdace33fa564e1e60453f2941dafc95539c99878b0d32746950394b9dd4d4`.
DVC does not download the raw CSV.

## Fixed data and selection contract

[Protocol v2](SELECTION_PROTOCOL.md) preserves historical train/calibration/test
memberships and subdivides historical tune. Expected sizes are train 33485,
checkpoint 2389, risk/tune 2390, calibration 4786 and test 4787. The outer split
uses the historical `0.667`, not `2/3`; the new inner split uses 0.50 and seed 42.
`prepare_data` is the sole producer of all five persisted ID lists.

CNN checkpoint selection and early stopping use checkpoint. Both backends are
scored on checkpoint Macro-F1 and the backend is frozen before risk threshold
analysis. Exact ties choose baseline. Threshold analysis uses risk/tune only.
The frozen backend must meet the existing risk gate; there is no backend fallback
based on risk results. The historical two-point coverage promotion rule no longer
selects the production backend. Calibration and test reports do not affect it.

## Complete local execution

Train in a separate checkout with committed, LF source and no serving process
using its output directories. Set `APP_ENV=test`, `MLFLOW_TRACKING_ENABLED=false`
and `MPLBACKEND=Agg`. On Windows set `DVC_SITE_CACHE_DIR` to a writable cache if
ProgramData is inaccessible. Activate the intended environment so DVC subprocesses
use its Python. The verified CPU run uses `OMP_NUM_THREADS=4` and
`MKL_NUM_THREADS=4`.

Run `dvc repro --force --no-run-cache`, then `dvc repro` again without changes.
The second run must skip all 18 stages and `dvc status --json` must be `{}`.
DVC deletes stage outputs before rebuilding them. Never repair a failed risk gate
by restoring an old threshold, lowering the target or switching the backend.

Models, CNN sidecars, source metadata, prediction provenance, frozen selection,
thresholds, reports and lock must come from the same run. `/model-info` checks
report/model hashes. ECE/Brier come from calibration; classification and routing
come from test. `auto` additionally verifies selection, threshold and model hashes.

## Source and prediction provenance

Training metadata includes `git_commit`, `git_dirty`, `source_tree_sha256` and
`source_provenance`. The snapshot contains exact base64 bytes and SHA-256 hashes
of all Python files under `src`, dependency profiles, `params.yaml`, `pyproject.toml`
and `.gitattributes`. Training fails if the source snapshot or HEAD changes while
it runs. Snapshot dependency coverage is regression-tested. Git may become dirty
because tracked generated outputs are rebuilt; the recorded source bytes still
identify the exact committed training source. Persisted split hashes and data
identity are separately captured by DVC and the dataset metadata.

`evaluate_cnn` binds test CSV bytes to the model, vocabulary, labels and config in
`cnn_test_predictions.provenance.json`. Routing verifies that binding and checks
that the threshold references the same model. Missing/stale provenance fails
closed. Regenerate predictions with the intended model; never fabricate a sidecar
for an older CSV. DVC tracks these inputs directly.

## Fresh-checkout validation

A fresh checkout needs the raw CSV, all cached model objects, and ignored
`cache: false` prediction CSVs. These CSVs are not recovered by `dvc pull`; retain
the exact run's generated files, verify their lock hashes, or regenerate them with
the matching model and source. Use `dvc checkout` from a verified cache, then
require an empty `dvc status --json` using a fresh DVC state database.
Artifact-only CI does not have the raw CSV or ignored predictions and cannot
substitute for this full check. Remote pulls require credentials. New local model
objects must be uploaded separately before a remote-only checkout or deployment
can use a new release lock. No upload is implied by local reproduction.

## Historical evidence and limits

The previous model pair had incomplete training-source identity. It is archived
in [protocol-v1-summary.json](history/protocol-v1-summary.json); the complete local
backup is `.checks/protocol-v1-preserved`. Do not retrofit a current source snapshot
onto those old models.

The [LF migration archive](history/2026-11-11-lock/README.md) preserves the original
CRLF dependency record and its byte-verified DVC-generated LF migration. That
migration was not new training. The v2 lock is generated by actual execution.

Earlier [local verification notes](history/2026-11-11-reproduction.md) and
[audit remediation checks](AUDIT_REMEDIATION_2026-11-11.md) are dated historical
records. See [maintained release status](RELEASE_STATUS.md) for the current run.
Previously inspected test results remain descriptive evidence; formal new
confirmatory claims require genuinely new data. Seeds alone do not promise
bit-identical results on different platforms/hardware.
