## Source changes awaiting a new pipeline run

The second-audit fixes add recoverable training source snapshots, direct CNN
routing model dependencies and prediction/bundle validation. They have not been
used to replace the preserved production artifacts. CNN routing now requires a
provenance sidecar generated by a real `evaluate_cnn` run. Older CSVs without that
record fail closed.

The LF lock is an explicit newline-only migration of the historical run, with
[original lock, LF lock and migration evidence](history/2026-11-11-lock/).
The two fresh-checkout empty-status checks cover that historical source tree
and migrated lock. Functional source changes made afterward correctly invalidate
stages. An empty `dvc status` for the current code has not been claimed or forced.

The tune/checkpoint/risk-selection design is awaiting a separate decision. No
split, performance report or model artifact has been changed for that decision.
See [options and costs](EXPERIMENT_DESIGN.md). Local commits were subsequently
authorized by the user. Push, merge, deployment and model upload remain outside
the executed scope.

Local checks for these source changes are recorded in the
[remediation verification record](AUDIT_REMEDIATION_2026-11-11.md). Historical
87-test and 70-test counts elsewhere are dated results for earlier code.
